## What the native smoke test exercises

`desktop/test/native-smoke.cjs` creates a temporary project and app profile. It begins without a project and exercises native folder selection, cancellation, an unavailable folder, persistent failure, retry, full path confirmation and the next-step guide. It then saves a provider connection to a localhost model fixture, checks API success/failure/retry and modal status persistence, updates new-task defaults with a visible scope confirmation, runs a specialist through the real shared core, reloads the page, saves a generated HTML output through a real diff, rejects an external-file conflict, reloads and saves a fresh edit, searches actual message content, checks that task focus survives unchanged polling and that attention filtering excludes ready/completed tasks, opens another window, resolves conflicting drafts, configures three dummy connections without making paid calls, checks role-model isolation across conversations, opens the capability pages and messaging form, verifies that canceling project selection keeps the current task/draft, verifies that direct terminal proxy requests cannot bypass native confirmation, executes a harmless confirmed `echo` command, saves an unsent draft, quits and restarts.

The final package test additionally asserts that the renderer is running in the packaged app. Python and UI assets come from the bundle. Screenshots use the local fixture and are not evidence of real commercial-provider access. Native consent dialogs are substituted only through the external test driver inside its isolated fixture; production dialogs are not overridden. No diagnostic quit controls or test command bypasses are shipped.

The smoke test uses Playwright's Electron driver and requires the native process to exit with code 0 within 20 seconds. A 240-second overall deadline prevents stalled CI, extended to 420 seconds for the slower Windows runner. The beta.6 Windows run reached the terminal checks but exceeded the old overall deadline; its timeout is not recorded as a pass. The updated workflow must establish the result for the new head. The test requires the final restart and shutdown to succeed before writing passing evidence. This previously exposed a real multi-window cleanup defect: accessing a destroyed window to retrieve its ID interrupted quit. Window IDs are now captured before destruction, and unexpected cleanup errors are recorded instead of silently disappearing.

## Validation still required for public release

- Hands-on acceptance on supported desktop environments. Automated three-platform build and packaged smoke results do not establish every OS permission or desktop environment behavior.
- Real OpenAI/Anthropic/DeepSeek media/account access and Telegram/Slack/Discord callbacks and replies. No real platform messages were sent in this work.
- An operator-managed real HTTPS remote server and a second physical device. Shared-session authentication is tested locally; this does not establish real TLS deployment or offline synchronization.
- OS notifications, tray behavior, global shortcuts, real OS drag-and-drop and credential prompts across the target platforms. The code and opt-in controls exist; automated fixture checks do not establish every OS permission behavior.
- Developer ID signing/notarization and Windows Authenticode credentials. The local macOS beta is ad-hoc signed and not notarized. It is not being advertised as a signed public release.
