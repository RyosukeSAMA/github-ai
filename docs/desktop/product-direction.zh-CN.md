# Pantheon Desktop 产品方向与能力规划

状态：2026-10-20，英语界面与白色主背景交互原型。本文为产品设计与实现目标，不是已上线功能清单。现有可用产品基线为 v0.4.0 Web/CLI；桌面尚未接入真实核心或打包。

## 定位

Pantheon Desktop 是面向本地项目和长期任务的多神协作工作台。用户可以问一个问题，也可以交付整个任务：明确上下文 → Hermes 规划 → 合适的神执行 → 审阅成果 → 保存或继续。

客户端需要覆盖 Web 的核心能力，并扩展本地工作流、持续任务和系统集成。增加功能不等于把所有按钮同时摆出来；默认路径仍应允许新手选一家供应商、选一个项目、描述目标并收到成果。

Web 继续提供轻量聊天、工作区和管理入口；CLI 服务终端与脚本；桌面提供完整工作台。共享能力修复应回到同一核心，不为了区分产品而削弱 Web，也不复制一套模型、权限、预算或调度逻辑。

界面语言统一使用英语，默认白色主背景、浅蓝灰分区、柔和蓝色按钮及少量角色色；具体规范见 [Visual system](visual-system.md)。保留深色选项，用户输入和文件内容不强制翻译。

以下是基于官方资料的设计取舍，不是三家功能的完整比较。来源核对日期为 2026-10-20。

| 参考 | 有依据的交互与能力 | Pantheon 的设计选择 |
| --- | --- | --- |

## 桌面比 Web 扩展哪些能力

“共享核心已有”不代表桌面已经接入；以下各项均需单独完成桌面验收。

| 能力 | 当前 Web/CLI 基线 | 桌面目标 | 阶段 |
| --- | --- | --- | --- |
| 对话、多角色和模型配置 | 已有；连接与会话模型分开管理 | 保持全部能力，提供角色分配面板与清楚的当前任务配置 | 首版 |
| 多任务总览 | 已有任务记录与恢复能力 | 项目分组、运行中/等待处理/完成状态，多个任务独立停止与继续 | 首版 |
| 本地项目 | 已有受约束的工作区、文件和工具 | 原生目录选择、拖入、系统文件管理器打开、文件变化提示 | 首版 |
| 成果与审阅 | 已有附件、文件、预览与任务结果 | 跨任务成果库、来源/版本信息、代码/文档差异，写入前核对冲突 | 首版；复杂版本比较后续 |
| 终端 | 已有本地终端与原生 Windows 能力 | 工作区绑定终端、任务与终端切换，命令/审批/输出相互定位 | 首版 |
| 工程隔离 | 不作为当前桌面已交付能力 | Git 分支/worktree 选择、隔离修改、差异审阅和明确的合并操作 | 第二阶段 |
| 技能、MCP、记忆与渠道 | 共享核心已有；渠道真实账号验收待补 | 能力中心显示状态、来源、项目范围与设置入口 | 首版接入已有能力；扩展发现后续 |
| 多模态 | 已有图片/PDF、图像生成与转写；真实账号验证待补 | 拖入、预览、明确供应商/文件范围、产出可回到成果库 | 首版接入已有能力 |
| 自动化 | Chronos 本地调度已有 | 规则编辑、下次运行、历史记录、交付位置与后台状态一处管理 | 首版 |
| 后台与系统集成 | Web 依赖后台服务，CLI 可单次/连续运行 | 关闭窗口与退出分开；可选托盘、完成/失败/审批通知、启动入口 | 首版 |
| 多窗口与快捷入口 | 浏览器标签/终端窗口 | 独立任务窗口、布局记忆、全局唤起和系统级快捷键 | 第二阶段 |
| 模型与费用 | 已有预算、任务/角色/阶段用量 | 单家/混用、成本可见、额度提醒。节省/均衡/质量方案均显式应用 | 首版；经过定价/能力验证的方案后续 |
| 安装与更新 | 一行安装与更新/回退已有 | 用户无需准备 Python；系统安装包、版本通知、备份和失败回退 | 首版 |
| 跨设备/远程主机 | 不作为当前桌面已交付能力 | 明确本地/远程机器、凭据与文件边界；按用户配置接入 | 后续 |
| 浏览器/桌面应用操作 | 不作为本轮已实现能力 | 选做扩展；先明确系统授权、可见操作范围与停止方式 | 后续独立评审 |

系统通知、托盘或多窗口是客户端特有入口；任务、审批、额度和恢复语义仍归共享核心。相同能力可逐步向 Web 开放，不人为制造限制。

## 原型的信息架构

- **工作台**：任务目标、议事厅阶段、成果/协作记录/变更审阅/文件。右侧按需查看上下文与分配，底部继续任务。
- **任务中心**：所有任务、运行数量、等待处理和独立控制。原型最多模拟两个同时运行的任务；此限制不是正式版并发承诺。
- **成果库**：文档/网页/研究筛选、来源任务跳转。正式版增加搜索、版本与保存位置。
- **项目文件**：目录树、内容预览与差异，文件操作限定到用户选择的目录。
- **自动化**：Chronos 规则与执行记录。电脑需开机并保持唤醒；云端持续执行属于另一个交付范围。
- **能力中心**：诸神模型、技能、工具/MCP、记忆、消息渠道和桌面扩展。状态明确区分已配置、已验证、不可用与待实现。

**专注布局**保留任务入口、成果和输入；隐藏阶段与高级管理入口。用户随时能切回专业布局，也可通过命令菜单打开需要的工具。布局不改变运行权限、预算和任务状态。

**专业布局**展开协作阶段与能力管理，适合同时处理多个项目、文件、终端和变更。首版不强迫用户开满所有面板。

## Pantheon 自有的三条产品规则

1. **单家与混用同等完整**。新手可让所有聊天角色使用一家已配置供应商；高级用户可分别分配。选择混用不等于必然更贵，成本取决于单价、上下文和调用次数；并行、多轮复核通常会增加调用量。未完成定价和能力核对前，不自动把“节省/质量”偏好映射到具体模型。
2. **每个任务能回答“谁做了什么”**。展示角色、阶段、输入范围、交付物、状态和用量。展示执行摘要和工具结果，不承诺获取模型私有推理。
3. **桌面增强以完整交付为目标**。本地文件、成果预览、审阅、后台和恢复串成一个工作流；模型名和技术参数按需展开。没有真实接入的功能必须标清楚，不用模拟状态代表成功。

## 实现顺序与可验收结果

### 第一阶段：能安装、能完成真实工作

先做最小跨平台桌面壳与打包样机，确认 Python 核心、依赖、端口/认证、后台归属、目录选择和单实例。随后接入已有任务/会话、增量事件、模型配置、用量、文件/终端、审批、恢复、成果与自动化。

完整验收应能做到：安装 → 选目录 → 配一家模型 → 完成真实任务 → 审阅和保存成果 → 查看用量 → 关闭窗口/重开 → 找到任务 → 升级或回退。Windows/macOS/Linux 各自验收，不以浏览器原型替代原生测试。

### 第二阶段：专业效率

增加任务独立窗口、工程隔离/worktree、文件变化提示、更多预览格式、快捷入口、布局记忆，以及有依据的模型方案。多个写入任务需要明确锁定/冲突检查；不能把并行等同于可同时改同一文件。

### 后续扩展

远程主机、跨设备和可选的浏览器/桌面应用操作独立排期。远程文件不能误当作本地文件，桌面常驻不等于关机后仍能运行。

## 本次原型实际实现的边界

可操作：导航、两个任务模拟并行与分别停止、任务草稿/模式/模型隔离、成果类型筛选与来源跳转、接受/退回示例变更、专注/专业布局、深浅主题和命令菜单。

未实现：真实模型调用、真实文件/终端、Git/worktree、原生目录/托盘/通知、多窗口、安装包和后台管理。原型内存状态刷新即重置，没有保存密钥。真实供应商、多模态和消息渠道账户缺口继续保留，不在设计验证中冒充通过。
